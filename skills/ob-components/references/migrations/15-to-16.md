# Component Migration

Migration notes for Oblique 15 to 16. Oblique 16 is the active release and
Oblique 15 is in maintenance. Updates must move through each major version.

## Upgrade procedure

1. Check `package.json` for the installed Angular and Oblique versions.
2. Run the next major update with the Oblique CLI:

   ```shell
   npx @oblique/cli@16 update
   ```

3. Review the schematic diff and the published [Oblique changelog](https://github.com/oblique-bit/oblique/blob/master/projects/oblique/CHANGELOG.md).
4. Run lint, tests, and the application. Keep unrelated changes separate.

## Cross-cutting API change

Many component inputs and outputs moved to Angular signals in Oblique 16.
Inputs are readonly signals and outputs are `OutputEmitterRef` values. Code
that reads component state directly must use the signal access pattern. Code
that subscribes to old output observables must use the current output API.

The schematics handle many source changes. Review every generated change,
especially when a component is accessed from TypeScript rather than only from
a template.

## Component-specific changes

### Alert and autocomplete

- Alert `type` and `hasRoleAlert` are readonly signals.
- Autocomplete inputs and `selectedOptionChange` use signal-based APIs.
- Autocomplete null input handling and option positioning also changed. Read
  the current autocomplete reference after the update.

### Column layout

`left`, `right`, `noLayout`, and `wider` are readonly signals. The v16 layout
also changes overflow behavior. Test independently scrolling columns and
initially closed panels.

### External link and file upload

- External-link inputs are readonly signals.
- File upload inputs and upload events use signal-based APIs.
- Angular 22 uses `fetch` by default. File upload progress requires
  `withXhr()` in `provideHttpClient()`.

### Master layout

- `ObMasterLayoutConfig.locale` is removed. Use `translate.locales` in
  `provideObliqueConfiguration`.
- `focusElement` is renamed to `focusElementById`.
- Navigation and layout state uses signals.
- `active` on `ObINavigationLink` is no longer updated as before. Use the
  router or current navigation signals.
- `serviceNavigationConfiguration` is replaced by
  `updateServiceNavigationConfiguration`.

### Navigation, popover, and selectable components

- Nav-tree inputs use signals and its filter pattern is optional.
- Popover inputs and `visibilityChange` use signal-based APIs.
- Selectable state uses signals. Check the helper migration reference for
  related selectable behavior.

## Verification checklist

- [ ] Component inputs and outputs compile with the signal-based API.
- [ ] Master layout configuration uses `provideObliqueConfiguration`.
- [ ] Navigation focus calls use `focusElementById`.
- [ ] File upload progress uses `withXhr()` where Angular fetch is active.
- [ ] Keyboard, focus, and screen-reader behavior still passes review.
- [ ] Lint, tests, and a production build pass.
